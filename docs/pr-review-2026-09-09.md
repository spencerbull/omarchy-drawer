## PR #1: scalar profile IPC and host compatibility

[Draft PR #1](https://github.com/spencerbull/omarchy-drawer/pull/1), head `307652eb5909ac073c7f21333455c2f6ee58a0be`, based on main `c051f5789b97aec0c08b81d60d100d12ca5dc3f5`.

Recommendation: retain the scalar IPC proposal for a separate compatibility change. Do not pull the whole draft into the visual redesign. No newly introduced correctness defect was found in the static pass under its declared API 1 contract, but adoption is gated by:

- The new `drawerApiVersion === 1` requirement in `BarWidget.qml` disables opening and saving on the existing unversioned host extension. The contributor documents the requirement; plugin and host must be upgraded together.
- The revised installer only reverses its exact revised patch. It does not upgrade or remove the previous extension. Existing users need the previous patch to reverse it, or a separately reviewed migration path.
- [Workflow 34395873272](https://github.com/spencerbull/omarchy-drawer/actions/runs/34395873272) is `action_required` with zero jobs/check runs. Contributor-reported test passes are not independently verified CI results.
- Native desktop acceptance is explicitly outstanding, including keyboard/focus, scrolling, monitor/orientation, and scaling checks.

The detached scalar `status`, `selectProfile`, and `setWidgetVisible` interface fits Drawer ownership well. The lookup-table optimizations are reasonable. Virtualized rows could help unusually large catalogs; the draft retains the previous custom controls and does not address the visual redesign itself.

The design branch starts from main and adopts no contributor implementation. It independently adds native controls and pointer/keyboard coverage. A future IPC PR should rebase onto this layout and carry a tested host upgrade path.

## Runtime follow-up

Live verification of the design exposed an inherited persistence defect: host-injected nested Qt sequences fail `Array.isArray`, so the original settings decoder discarded saved profiles at startup. The native fixture reproduced this with preconfigured profiles. Commit `2215233` materializes plain JSON at the settings boundary and tests startup persistence before drag interaction; removing that fix fails the regression. PR #1 retains the old decoder, so it should include this fix when rebased.
